# Digest

> Stop collecting. Start knowing.

**Digest 是一个用 AI 并行 Agent 把你的信息收藏夹蒸馏成主题式知识书的开源工具。**

别人帮你读一篇文章。Digest 帮你读完一个月。

---

## 它解决什么问题

每个知识工作者都有一个"信息坟场"：

- 微信收藏夹里几百篇"稍后阅读"
- 浏览器书签里几十个"有空看看"
- 下载文件夹里成堆的 PDF
- 付费社群里的聊天精华

**你从来不看。不是因为你懒，是因为信息量远超人类的处理能力。**

现有的 AI 工具帮你读**一篇文章**。你需要的是有人帮你读完**一个文件夹**。

## 核心理念

### 蒸馏 ≠ 摘要

| | 摘要 | 蒸馏 |
|---|---|---|
| 本质 | 信息压缩 | 知识提纯 |
| 输入 | 1 篇文章 | 100 篇文章 |
| 输出 | 更短的文章 | 结构化的洞察 |
| 价值 | 丢弃噪音 | 交叉验证 + 发现关联 |

Digest 做的不是"把长文变短"，而是"从大量信息中提取真正值得记住的东西"。

### 每个观点告诉你四件事

1. **谁说的** — 信息源质量（⭐1-5星）
2. **多数人怎么看** — 共识还是分歧
3. **读完你能得到什么** — 读后收获（不是复述，是认知增量）
4. **什么变了就失效** — 关键变量

## 快速开始

### 方式一：Claude Code Skill（推荐）

```bash
# 安装
npx skills add MeteorPolaris/digest

# 使用：在 Claude Code 中直接说
"帮我把 ./my-data 做成 6 月精华书"
```

### 方式二：Prompt 模板

复制 [`prompt/digest-template.md`](prompt/digest-template.md) 的内容，粘贴到任何 AI 对话框（ChatGPT、Gemini、Cursor 等），替换目录路径和月份即可。

### 方式三：手动运行

```bash
# 1. 克隆仓库
git clone https://github.com/MeteorPolaris/digest.git
cd digest

# 2. 把你的文件放进一个文件夹
mkdir my-data
# 将你的 .txt / .md / .pdf 文件放入 my-data/

# 3. 用 Digest 的提示词让 AI 处理
# （见 prompt/digest.md）

# 4. 生成 HTML
python scripts/generate_html.py ./digest-output

# 5. 查看
open ./digest-output/index.html
```

## 输入格式

Digest 接受任意目录，自动识别文件类型：

| 格式 | 典型内容 | 处理方式 |
|------|---------|---------|
| `.txt` | 每日资讯笔记、群聊精华 | 逐条解析，去噪去重 |
| `.md` | 付费文章、深度分析 | 全文读取，提取观点+数据 |
| `.pdf` | 券商研报、行业报告 | 精读最重要的 + 文件名分类其余 |

目录结构示例：

```
my-data/
├── 星球内容/          ← 每日 txt
│   ├── 2026-06-01.txt
│   ├── 2026-06-02.txt
│   └── ...
├── 文章/             ← 按周分组的 md
│   ├── 0601-0607/
│   └── 0608-0614/
└── 研报/             ← 按日期分文件夹的 PDF
    └── 2026-06-01/
        ├── [半导体]xxx.pdf
        └── [电池]xxx.pdf
```

## 五层蒸馏流程

```
原始信息 → Scanner → Extractor → Clusterer → Synthesizer → 知识书
  (噪音)    (扫描)    (提取)      (聚类)       (合成)       (精华)
```

1. **Scanner** — 扫描目录，识别文件类型和结构
2. **Extractor** — 并行读取各类文件，提取结构化信息
3. **Clusterer** — 按主题聚类，人工确认
4. **Synthesizer** — 每个主题一个 Agent，并行合成
5. **Renderer** — 生成导览 + 交互式 HTML

## 自我进化

Digest 会自动记录每轮运行中遇到的问题和解决方案：

```markdown
## 问题：研报 PDF 覆盖率仅 4.6%
- 现象：324 份只读了 15 份
- 原因：Agent 自行决定"选最核心的"，导致大量被跳过
- 解决：设定覆盖率阈值，低于则自动补救
- 下次：提取完成后强制检查覆盖率
```

下次运行时，AI 先读这个文件，避免重复踩坑。**越用越好。**

## 为什么是开源

护城河不是代码。任何人都能写一个 prompt 让 AI 做类似的事。

护城河是：
- **方法论** — 两波流水线、覆盖率保障、自我进化
- **模板** — 主题分册结构、HTML 渲染、导览格式
- **社区** — 用户分享自己的主题定义、配置、最佳实践
