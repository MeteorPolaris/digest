# Digest 架构设计

## 概述

Digest 是一个 AI 知识蒸馏引擎，通过并行 Agent 将大量零散信息蒸馏成主题式知识书。

## 核心理念

### 蒸馏 vs 摘要

摘要（Summarization）是信息压缩：1000字 → 200字，本质是丢弃。
蒸馏（Distillation）是知识提纯：100篇文章 → 8个洞察，本质是增值。

### 两波流水线

```
第一波：提取（并行）
  ├── Agent A：读取 txt → 结构化数据
  ├── Agent B：读取 md → 结构化数据
  └── Agent C：读取 pdf → 结构化数据

第二波：综合（并行）
  ├── Agent 1：主题A → 分册
  ├── Agent 2：主题B → 分册
  └── Agent N：主题N → 分册

终审：导览 + HTML
```

为什么分两波？
- 提取阶段每种文件类型一个Agent，互不干扰
- 综合阶段每个主题一个Agent，读取的是结构化数据（不是原始文件）
- 避免同一文件被多个Agent重复读取

### 已知的坑

| 坑 | 原因 | 解决 |
|---|---|---|
| PDF读太多Agent溢出 | 一份研报可能几万字 | 每Agent最多精读5份 |
| Agent卡死无产出 | 攒到最后一起写 | 先写核心产出再扩展 |
| 覆盖率低 | Agent自行决定"选最核心的" | 设定覆盖率阈值 |
| 星球内容重复 | 同一事件多天出现 | 去重，按唯一信息点计数 |
| 上下文压缩断裂 | 对话过长 | 用任务系统跟踪状态 |

### 自我进化

每轮运行记录问题与解决到 `数据层/问题与解决.md`。下次运行时AI先读此文件，避免重复踩坑。

## 输出规范

### 主题分册结构

```
# {主题名}
## 本月核心观点          ← 3-5句话概括
## 信号地图              ← 表格：信号/强度/来源数/共识分歧
## 子主题一              ← 按逻辑线索组织
  ### 核心观点
  ### 关键数据
  ### 信息源与读后收获    ← 不是复述，是"读完你会理解什么"
  ### 共识与分歧
## 关键变量清单          ← 什么变了逻辑就失效
## 跨主题关联            ← 与其他主题的交叉点
```

### 导览

情报简报风格。每个主题3-5句话：
- 核心观点一句话
- 最大爆点/反常识点
- 信号强度 + 共识度
- 关键变量

### HTML

- 暗色主题（护眼、高级感）
- 左侧导航栏
- 全文搜索
- 可折叠子主题
- 标签颜色编码
